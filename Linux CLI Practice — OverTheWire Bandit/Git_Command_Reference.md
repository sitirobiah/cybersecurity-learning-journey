# Git Command Reference

| Command | Purpose |
|---|---|
| `git clone <url>` | Copy a remote repository locally |
| `git status` | Check repository status |
| `git log` | View commit history |
| `git log --oneline` | Show a short commit history |
| `git show` | Inspect a commit or Git object |
| `git branch -a` | List branches |
| `git remote -v` | View remote repository URLs |
| `git tag` | List tags |
| `git show <tag>` | Inspect a tag |
| `git add <file>` | Stage a file |
| `git commit -m "message"` | Create a commit |

## Basic Workflow

1. Check the repository with `git status`.
2. Stage the required changes with `git add`.
3. Create a commit with `git commit`.
4. Review the history with `git log`.

**Reminder:** Git commands can produce different results depending on the repository, branch, and current state.

## Key Lessons
- A Git repository contains more than the current version of its files.
- Commit history can help explain how a project has changed.
- Branches and tags provide different ways to reference repository history.
- Staging selects changes for a commit.
- Understanding command output is more useful than memorizing commands alone.
