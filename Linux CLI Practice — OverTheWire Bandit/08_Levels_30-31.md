# Bandit Levels 30–31: Git Tags and Repository Content

## Level 30 → 31: Inspect Git Tags

**Goal:** Learn how to inspect tags in a repository.

```bash
git tag
git show <tag_name>
```

- `git tag` lists available tags.
- `git show <tag_name>` displays information associated with a tag.

**Key takeaway:** Tags can mark specific points in a repository's history. They may contain useful information even when the current file does not.

## Level 31 → 32: Track and Commit a File

**Goal:** Practice adding a file to Git and creating a commit.

```bash
git status
git add <filename>
git commit -m "Add required file"
```

- `git status` checks the current repository state.
- `git add` stages a file for the next commit.
- `git commit` saves the staged changes in the local repository.

**Key takeaway:** Git does not automatically include every new or modified file in a commit. Files must be staged first.

> Always check the challenge's required filename and file contents before committing. These examples illustrate the general Git workflow.
